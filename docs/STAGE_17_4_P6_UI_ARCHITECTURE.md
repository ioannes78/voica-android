## UI choice
An in-detail child screen opened from a compact explicit “离线问答” action directly below current transcript action bar; available for current effective completed transcript in both reading and timeline modes, never on candidate preview. No fifth permanent tab, no new global navigation destination, no dialog/bottom sheet. Back exits QA first; preserve parent transcript scroll/mode. Clear session on actual exit, recording switch, current lineage change, or composition destruction; no automatic restore after recreation. Opening QA loads current snapshot through OfflineQaEvidenceResolver; entry visibility is not proof of source readiness. No persistence or saved-state transcript/chat payload. Child screen replaces detail body using existing root scaffold padding; use IME insets without double consumption, verify on device.

## Layout
Compact header “离线问答”, back, recording name/current lineage label, local-only indicator, clear conversation action. Scrollable conversation, initial guidance and sample questions, user message, validated claims with evidence links, partial/insufficient and typed failure states, per-answer copy. Fixed bottom composer (max 512 code points), submit/cancel; keyboard safe; shared global mini player below screen via parent Scaffold. Avoid unvalidated stream; no model raw output, no API keys, no cloud. Evidence row shows speaker (unknown/ambiguous when appropriate), derived canonical time range and excerpt; manual revision labeled, not verbatim original proof. Link enabled only after source and actual playback eligibility validation. No new fixed colors. Accessibility: text labels, meaningful semantics, contrast and font scaling, tap targets 48dp where feasible. Preserve compact density without clipping.
