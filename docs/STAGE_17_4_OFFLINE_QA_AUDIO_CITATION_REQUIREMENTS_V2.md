# Stage 17.4 — 离线问答与原始语音证据回链 V2
Status: USER APPROVED / P0 DOCUMENTED. Supersedes V1 for implementation; retain V1 history.
Scope: current recording/current effective transcription only; offline natural-language Q&A, bounded follow-ups, Chinese lexical retrieval, speaker/time filters, multiple per-claim evidence, original audio seek, copy, explicit insufficient/partial answers. Page-memory session only; no persistence, Room v17 unchanged; no cross-recording/RAG/embedding/FTS migration. No cloud/API-key/upload.
Use StructuredTranscriptInput and existing Gemma 4 E2B/LiteRT-LM 0.18.0 AppLocalLlmRuntime; AUTO + JSON schema remains CPU, no second engine or M4B dependencies. Separate Q&A contracts; each claim has nonempty request-allowlisted evidence IDs. Status ANSWERED/PARTIAL/INSUFFICIENT_EVIDENCE; distinguish invalid output, changed/unavailable source, busy, cancelled and runtime failure. No model-provided time truth. Do not present unvalidated streaming text as final. Treat transcript and question as data, not instructions; reject unsupported references, malformed/oversized outputs; at most one bounded repair for recoverable structure failures, never retry uncertain native ownership. Numeric/unit checks where deterministic; semantic support requires annotated evaluation, not guaranteed by ID checks. Do not claim exhaustive coverage from bounded retrieval.
Snapshot: atomically read current effective source using short Room read transaction outside inference; bind recording/transcription/revision/alignment/canonical asset/profile/SHA/total samples plus ordered units and evidence identity/source/speaker/sample ranges/text to Q&A-specific digest; existing inputContentDigest unchanged. Revalidate before generation, publishing and seek. Evidence IDs positional within snapshot only. Exclude unanchored text from audio evidence; label manual revisions, do not imply edited text is verbatim audio. Validate range and actual playback asset, disable stale/unavailable links; use existing seekAndPlay(recordingId,sampleIndex). 
Retrieval: deterministic normalized Chinese bigram/keyword/phrase/numeric matching against snapshot, speaker/time filters, relevance ranking with stable tie break, neighbor expansion, dedup, bounded whole candidates. Existing FTS4 stays untouched. Initial provisional limits: maxNumTokens 4000, estimated prompt ceiling 2528, maxOutputTokens 1024, topK candidates 12, neighbors ±1, question 512 chars, last 2 turns subject to budget; no speculative decoding, no LLM rerank. Bounds include system/schema/history and evidence overhead; reject oversized indivisible evidence or explicitly mark incomplete, never silently truncate facts. Parameters require tests before final freeze.
UI: entry on transcript reading page, existing theme/player/Mini Player, local state for retrieval/generation/validation/answer/refusal/error/cancel. Cancel on leaving session, no automatic resume, isolate recording/revision changes. Clear stale responses; copy only validated content. Protect recording/BLE/ASR/playback and summary jobs; atomic whole-business-task admission including Direct/Long start/resume and Q&A, deny busy/poison, hold through cleanup. No frozen runtime/prompt/checkpoint changes.
Acceptance: legal citations and canonical mapping 100% on fixtures, zero cross-recording/stale refs, zero critical numeric fixture errors, target candidate recall >=90%, supported claims >=95%, correct insufficient refusal >=95% on labeled evaluation; no cloud or parallel native owners. Physical seek accuracy/performance thresholds to be established before QA. Formal device acceptance gated by 17.3 Freeze per dependency revision.
